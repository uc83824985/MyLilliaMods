# 远程开发依赖与构建

范围：远程编辑、编译、规则检查；不运行游戏或运行时测试插件。

## 依赖结论

编译需要 .NET SDK（目标框架 net6.0）和下列开发引用。仅安装通用 BepInEx 不足以编译：`BepInEx/interop/Assembly-CSharp.dll` 等接口程序集由本游戏生成，包含插件调用的游戏与 Unity API。

| 内容 | 插件／测试项目编译 | 纯规则检查 |
| --- | --- | --- |
| BepInEx core 中 4 个引用 DLL | 需要 | 不需要 |
| 本游戏生成的 interop 中 19 个引用 DLL | 需要 | 不需要 |
| NoviceSuccubusLillia_Data | 不需要 | 不需要 |
| 游戏 EXE、GameAssembly.dll、UnityPlayer.dll | 不需要 | 不需要 |
| LilliaSystem.dll、.codex/LilliaSystem | 不需要 | 不需要 |
| 存档、当前游戏配置、运行日志 | 不需要 | 不需要 |

`tests/ChaseRuntimeChecks` 编译额外使用 Addressables 等接口，但加载真实预制体只发生在游戏内运行时。本范围不执行它。`tests/RulesChecks` 直接包含纯 C# 的 Rules.cs，不引用 BepInEx 或 Unity；运行时需要兼容 net6.0 的 .NET 运行时。

## 开发引用包

本地执行：

```powershell
./tools/Export-DevReferences.ps1
```

输出 `artifacts/lillia-dev-references.zip`，仅包含项目声明引用的 23 个 DLL（4 个 core、19 个 interop）及 SHA-256 清单 `manifest.json`。不包含任何游戏原生文件、数据目录、资源包或存档。可以通过 `-BepInExRoot` 指定其他安装的 BepInEx，通过 `-OutputPath` 指定输出路径。

源码仓库与引用包一起转移到开发环境。包和解压目录默认被 Git 忽略，单独作为环境依赖传输；仅同步 Git 源码不会自动获得这些 DLL。游戏版本或 interop API 更新后，应重新导出对应引用包。

## 远程构建

在仓库根目录，将包解压到 `references/`：

```text
MyLilliaMods/
  Directory.Build.props
  references/
    BepInEx/
      core/
      interop/
    manifest.json
  src/
  tests/
```

PowerShell：

```powershell
Expand-Archive -LiteralPath /path/lillia-dev-references.zip -DestinationPath references
```

Linux shell：

```bash
unzip /path/lillia-dev-references.zip -d references
```

编译及不依赖游戏的检查：

```text
dotnet build src/LilliaChasePrototype/LilliaChasePrototype.csproj -c Release
dotnet build tests/ChaseRuntimeChecks/ChaseRuntimeChecks.csproj -c Release
dotnet run --project tests/RulesChecks/RulesChecks.csproj -c Release
```

如果环境只提供较新的 .NET 运行时，可在规则检查命令末尾添加 `--roll-forward Major`。构建所需 net6.0 引用包应已安装或可由 SDK 恢复。插件编译产物位于 `src/LilliaChasePrototype/bin/Release/net6.0/`。

`Directory.Build.props` 优先使用仓库内 `references/BepInEx`，其次使用仓库旁边的本地 `../BepInEx`。也可显式覆盖：

```text
dotnet build src/LilliaChasePrototype/LilliaChasePrototype.csproj -c Release -p:BepInExRoot=/absolute/path/BepInEx
```

远程本范围不执行 `tools/Test-Runtime.ps1`；该脚本需要完整游戏安装，只用于本地入游戏验证。

## 已验证的边界

在游戏目录之外的新建临时目录，仅复制源码、Directory.Build.props 和解压后的 23 个引用 DLL。未复制 EXE、GameAssembly.dll、UnityPlayer.dll、NoviceSuccubusLillia_Data、System 插件或本地配置。

插件和运行时测试项目均 Release 编译通过，零警告、零错误；15 项纯规则检查通过。此项验证证明引用闭包足够支持不运行游戏的开发；验证在本地 Windows SDK 上完成，未声明已经验证远程 Linux 环境。
