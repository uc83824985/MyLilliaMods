# 0.1.0 抓捕与闪避实现记录

本文记录 0.1.0 的历史实现。当前 0.1.1 已修正暂停动画导致的骨骼下沉、参数提交和磁盘重载，并精简了参数；最新行为及证据见 [0.1.1 修复记录](0.1.1下沉与参数修复.md)。

实现日期：2026-10-13。工程位于 `src/LilliaChasePrototype`，独立于 `.codex/LilliaSystem`。当前六份设计规格中的主动技能、完整搜索循环和警察风格尚未实现。

## 原生接入

普通警察和可诱惑警察在 `CheckAlertCost` 中直接检查距离与遮挡后调用 `OnPunishment`，没有原型要求的前摇。插件在该原生方法作用域内临时将 `catchDistance` 设为 0，正常和异常退出均恢复，保留警戒逻辑；独立状态机在前摇结束时结算，再调用原生监听器。

警长真实预制体使用 `NPCStateControl`，不是 `PoliceStateControl`。插件按 `NPCTagHolder.PoliceChief` 和实际 `PatrolStatus.Chase` 识别，且必须追踪主角才启动；命中时调用原生 `WorldController.Player_OnPunishment`。不会让普通 NPC 获得抓捕。

警察停止同时处理 `PatrolMovement`、寻路 `isStopped/updateRotation`、骨骼根运动和移动动画层。主角速度通过 `CharacterController.UpdateVelocity` 后置处理，保留 KinematicCharacterMotor 碰撞。闪避固定体力成本不叠乘 System 的跑动消耗倍率；临时体力字段在后置及最终清理中恢复，兼容 System 同方法的临时倍率和 finalizer。

## 动画尝试与当前结果

加载了 `police`、`police_chief`、`police_seducible` 三个真实 Addressables 预制体。三者使用 `NPC_Animator`，已有片段包括：

- `MCU_am_Stand_Idle_02`、`MCU_am_Loco_Walk_01`、`MCU_am_Loco_Run_01`。
- `Fainting_01`、`Fainting_Yamucha`、`Fainting_02`。
- `Spray_hit_[ Start / Loop / End ]`、`Disarray_[ Start / Loop / End ]`。

使用原生 `Animator.HasState` 检查 `Grab / Catch / Arrest / Reach`、对应 `Base Layer.*`，以及 `GrabMiss / CatchMiss / Miss` 候选，均未找到兼容状态。原有喷雾、混乱和昏倒动作属于其他行为，本轮不用于伪装抓捕。因此当前使用红光前摇和原地僵直，不宣称已经接入抓捕动画。

保留开发用 `GrabState / MissState` 参数。候选必须存在、能对应可确认片段、非循环且没有动画事件才尝试播放；根位移关闭，逻辑时钟独立。

待办：寻找或新增骨架兼容的抓取／挥空片段，再校准表现。原因是当前控制器没有相应状态，而非抓捕逻辑尚未接通。

## 可视化验证

扇形已实现并在真实图形设备上渲染确认；使用运行时 LineRenderer，不依赖编辑器 Gizmos。弧线与判定共享完整角和半径，青色方向对应当前动作承诺。截图：[抓捕扇形](../artifacts/capture-sector.png)。

红白光使用独立蒙皮外壳及独立材质，不改原渲染器、服装或原共享材质。无图形设备模式没有可用着色器，会记录原因；正常图形运行已确认红光和扇形可见。

原先尝试的 `OnGUI` 在本游戏检查环境中未正常回调，最终改为独立 Canvas 参数面板。通过原生按钮监听器切换 Capture 页，并对渲染纹理进行像素检查和截图确认，见 [参数面板](../artifacts/parameter-panel.png)。

## 检查证据与实际边界

- Release 编译零警告、零错误；纯规则检查覆盖阶段边界、扇形边界、完美窗口与跨字段约束。
- 原生近距抓捕：启用插件时抑制旧结算；关闭接管后同一隔离情境恢复原生 Arrest；注入异常后原始距离仍恢复。
- 三类真实预制体：合法近距目标可以启动；模型根运动确实停止；转向遵守角速度与承诺；背后判定落空；后摇结束才恢复。
- 主角真实原生速度与 KinematicCharacterMotor：0.2 s 突进实际前进 2.000 m；墙面阻挡后停在 0.790 m，不穿墙。恢复倍率作用于最终正常速度。
- 多警察：第一名消耗一次完美保护，第二名仍可命中；只触发一次原生结果，清除本场动作。已经离开范围的普通扑空不消耗保护。
- 暂停不推进动作；参数修改不改变正在执行的动作；实体禁用可清理；配置拒绝 NaN 和非法窗口并支持保存重载。
- `runtime-with-system.log` 和 `runtime-without-system.log` 分别记录两种加载环境；临时测试 DLL 在检查后移除。System DLL SHA-256 保持 `106DA9FF2AA88CE26A3431CD65B1D9ACFFC4695F5D4BC9B16D14A4E1C8F90687`。

运行时检查使用隔离实体与原生组件，失败入口在测试插件中拦截以避免游戏奖惩和存档变更。测试中的 `expected alert fixture failure` 是故意注入的异常，用于验证清理，不是游戏内实际故障。

尚未自动验证完整关卡中实体键盘输入、不同服装下主角光效、复杂交互与地图边缘体验。初始速度和体力值也未宣称平衡；后续依靠实际追逃调参。开发期保留技术参数，后期再固定非玩法参数。
